# L0: the card language

Everything a card can say. If a construct is not here, it does not exist — there
is no escape hatch, and a card that reaches for one is refused with a reason.

The normative definition is `Splash/docs/ui-profile-l0.md`. This is the working
version: same language, ordered for writing rather than for specifying.

---

## The shape of a card

Five kinds of declaration, then views. Order is free; convention is this:

```
# level: L0
# model: <app id>

source <name>  sys.<capability>(<args>)     what the card needs fetched
state  <name>  { shape: …, initial: … }     what the card remembers
event  <name>  { <state>: <transition> }    what a tap does
copy   <name>  { class: …, en: …, zh: … }   words the card owns
component <Name>(<props>) { … }             a repeated piece
view <name> <Role>(…) { … }                 what to show
```

`view root` is where rendering starts.

An icon is a MEANING from a closed set, never a drawing:
`Icon(name: .bell)` beside a notifications row, `Icon(name: .search)`,
`Icon(name: .sun, size: .hero)`. ~50 names (bell, search, settings, calendar,
camera, heart, map, user, chevron_right, …); the theme decides the glyph.

## 1 · Sources — everything the card knows

```
source now sys.weather(lat: place.lat, lon: place.lon, fields: [temp, cond])
```

A source names a **catalogued capability** and binds its result to a name. You
cannot call anything else, and you cannot call it from anywhere but a `source`
declaration.

**Sources may depend on each other.** `sys.weather(lat: place.lat)` means the
runtime fetches `place` first. You never sequence this yourself and you never
re-resolve anything: the dependency is declared, so when `place` changes the
runtime knows `now` is stale.

**Every source has a lifecycle.** Branch on it:

```
copy loading { class: vocabulary, en: "Loading…" }
copy offline { class: vocabulary, en: "Can't reach the network" }
when now.$state == .pending { TextBody(text: copy.loading) }
when now.$state == .failed  { TextBody(text: copy.offline) }
when now.$state == .ready   { … the real card … }
```

**`copy.loading` has to be DECLARED like any other copy.** A `copy.x` that is
not declared is refused, by any route — this snippet is the most-copied lines in
the memory, and showing the use without the declaration is why cards come back
refused for `copy.loading is not declared`. Same for an empty-state string.

`.pending .ready .stale .failed` — four states, so "not yet" and "went wrong" are
never confused. Do **not** compare a value against `-9999` or check whether a
field is empty; that is what this replaces.

### Computed values from runtime capabilities

Use `sys.convert(amount: state.amount, from: state.from, to: state.to,
direction: state.dir, fields: [amount, value])` for unit conversion. Supported pairs in
either direction are `km/mi`, `m/ft`, `cm/in`, `kg/lb`, `g/oz`, `l/gal` (US),
`km/h/mph`, and `c/f`. Set unit names as text. `direction` is `fwd` (default) or
`rev`; reverse swaps the named units. The runtime owns the coefficients and
returns the validated input `amount` and converted `value`. Bind both display
values from this source; do not declare factors, offsets or formulas in the card.
Unsupported pairs return a failed source, never an invented value or exchange rate.

`sys.cities(fields: [...], unit: state.units)` accepts `c` or `f` (default `c`).
Its `temp`, `feels`, `hi` and `lo` are absolute temperatures in that unit.
`feels_delta` is feels-like minus actual temperature, also in that unit;
a Fahrenheit difference has a scale conversion without a 32-degree offset.
Bind `c.feels_delta` directly. Missing readings remain unavailable.

## 2 · State — what the card remembers

```
state city  { shape: text, initial: "" }
state units { shape: enum[c, f], initial: env.locale.temp_unit }
state open  { shape: bool, initial: false }
```

Shapes: `text`, `number`, `bool`, `enum[a, b, c]`. An `initial` is a literal or a
path — `env.locale.temp_unit` seeds from the device.

State is what makes a card interactive. It is also the only thing a tap can
change.

---

## 3 · Events — what a tap does

```
event open_quote  { selected: set($value) }
event toggle_units{ units: cycle(c, f) }
event back        { selected: clear }
```

Four transitions, and they are the whole vocabulary:

| | |
|---|---|
| `set(x)` | a literal, a token, a path, or `$value` — the payload the tapped element carried |
| `toggle` | booleans only |
| `cycle(a, b, …)` | advance through an enum in declared order, wrapping |
| `clear` | back to the declared `initial` |

An event may write several states at once; they commit together or not at all.

**`$value` is how a tap says *which*.** The element carries `value:` and the
transition receives it:

```
Row(on_tap: open_quote, value: m.ticker) { … }
```

---

## 4 · Copy — the words the card owns

```
copy feels { class: vocabulary, en: "Feels like", zh: "体感" }
```

`class` is required: `vocabulary` (a label you may write), `user-copy` (the
user's own words), `model-copy` (yours — and **it may not be rendered**, which is
the point of the class existing).

Anything a reader sees that is not data comes from `copy`. This is what makes a
card translatable.

## 4b · Theme — the one thing a card may say about how it looks

```
theme dark
```

Optional, at most one, and the name must be one of **`dark`** (the default, so
you may leave it out), **`light`**, **`glass`**, **`photo`**, **`vibrant`**,
**`minimal`** — or a THEME PACK: **`atro`**, **`atro_light`**, **`camo`**,
**`camo_light`**, **`taskplan_light`**. Anything else is
REFUSED.

A pack is a whole design system imported as a theme — its palette, its type
scale, its typeface, its corner language and its depth, minted from a
purchased design kit. `atro` is a dark indigo-on-navy fintech system
(geometric sans, soft navy glow, compact radii); `atro_light` is its light
mode. Declare a pack exactly as you would a mood, and compose axes over it
(`theme atro accent: .red`) when the request deviates from the kit's own look.

`camo` and `camo_light` offer the Camo dark and light component system;
`taskplan_light` offers Taskplan's light productivity system. All five packs
work across weather, stock and news. They choose native component styling,
typography, spacing and surfaces as well as palette.

This is the ONLY presentation statement L0 admits, and it is admitted because it
is not one: you are naming a MOOD, and the component kit decides what that mood's
page, panels, hairlines and ink actually are. You still never write a colour, a
font size or a pixel.

Choose a theme from explicit style requests or supplied context. An explicit
theme wins over a saved preference, which wins over a time-of-day suggestion.
For example, morning planning can use `taskplan_light` with airy density;
nighttime market monitoring can use `atro` with compact density; a reader who
prefers Camo can use `camo_light` by day and `camo` at night. Treat these as
examples, not mandatory app-to-kit assignments. Never infer the user's location,
local time or preferences when they have not been supplied. Without style context,
retain the app exemplar's theme. Changing context must preserve the app's sources,
required content and working controls. Reorder and group declared views when that
helps the stated task; use the catalogued semantic components, never painted text
or a full-screen image.

`photo` is for a card whose page IS an image (a `Photo` surface): its fills are
laid over a photograph rather than replacing it.

### Axes — the other coordinates of a theme

A mood may be followed by any of five axes, in any order:

```
theme dark accent: .amber radius: .none density: .airy
```

| axis | values |
|---|---|
| `accent` | `neutral` (default), `indigo`, `blue`, `red`, `green`, `amber`, `cyan`, `magenta`, `violet` |
| `radius` | `none`, `small`, `large`, `full` |
| `density` | `compact`, `regular` (default), `airy` |
| `emphasis` | `quiet`, `clear`, `poster` |
| `icons` | `filled`, `mono` |
| `feel` | `bright`, `calm`, `bold`, `premium`, `playful`, `warm`, `cool`, `minimal`, `inspirational` |

`feel` is the request's own language: declare it when the request names a
MOOD-WORD rather than a look — "make it feel premium", "轻快一点". It resolves
to axis defaults (a feel is never a tenth kind of thing; `premium` currently
means midnight ground, serif display, quiet emphasis, large radius), and any
axis you state explicitly overrides the feel's default. Prefer a feel over
hand-picking axes when the request speaks in adjectives; every feel value is
validated by a blind paired judge to actually read as its word.

Same contract as the mood: every value is a TOKEN naming an intent, never a
colour or a length. Four moods could only ever be four looks, and a corpus of a
hundred generated designs asked for square AND soft geometry, restrained AND
vivid palettes — one global setting cannot serve both sides of that.

`ground` and `accent` COMPOSE: `theme dark ground: .teal accent: .amber` is
gold-on-teal, the ink re-solved against the teal in-kit (every pairing ships
AA-clean by construction).

`accent` sets the card's INK, not just its highlights. The kit solves each
hue against each mood's ground and panel, so `accent: .amber` over `dark` is a
full gold ink while over `glass` it is a 60% pull — the strongest tint that
still clears 4.5:1 on both surfaces. You never state the strength; asking for
the hue is enough, and a hue that cannot carry body text on a given ground is
softened rather than allowed to go unreadable.

## 5 · Views — what to show

```
view root Surface {
  Col(gap: 4) { TextCaption(text: place.name) }
}
```

Roles nest. A view may reference another view by name.

**Branching** — `when <path> <cmp> <value>`, with `== != < <= > >=`:

```
when selected == "" { list }
when selected != "" { detail }
```

There is no `else`. Two complementary guards say it, and that is deliberate:
there is no expression form to negate with.

**Which is why a two-screen card uses an ENUM and not a flag.** A guard tests a
declared name against a declared value, so a `bool` gives you `when driving` for
the true case and nothing for the false one — `when driving == false` asks the
checker to accept an undeclared literal and is refused:

```
state screen { shape: enum[plan, drive], initial: .plan }
event go     { screen: cycle(.plan, .drive) }

when screen == .plan  { … }
when screen == .drive { … }
```

Two named screens have two guards that each say which screen they are. Use
`shape: bool` only where the true case alone needs rendering — a disclosure row
that expands.

**A guard is a STATEMENT wrapping elements — never an argument.** Nothing
inside a constructor's `(…)` may be a `when` or a `for`. Close the argument
list first, then wrap:

```
✗ Col(gap: 8
    when now.$state == .ready { TextRow(…) }
  )
  → refused: a `when` guard cannot appear inside an argument list; guards wrap elements

✓ Col(gap: 8) {
    when now.$state == .ready { TextRow(…) }
  }
```

**Every constructor argument is `name: value`, and commas separate arguments.**
A bare value, or a comma where the `:` belongs, is refused:

```
✗ TextValue(value, now.temp)
  → refused: expected ":" after argument name `value`
✓ TextValue(value: now.temp)
```

**Iteration** — over a declared collection, with a key:

```
for m, i in movers key m.ticker {
  Row(on_tap: open_quote, value: m.ticker) { TextRow(text: m.name) }
}
```

The key is what gives each row its identity, so a row keeps its state when the
list reorders. It must name a field of the item.

**Components** — a repeated piece with its own props and, if it needs them, its
own state:

```
component ForecastRow(day: record) {
  state expanded { shape: bool, initial: false }
  event toggle   { expanded: toggle }
  view Row(on_tap: toggle) { TextRow(text: day.dayname) }
}
```

A component reads its props, its own state, and card-level sources and copy. It
**cannot** read card state — pass it as a prop, so the dependency is visible.

## What is not here, and what to write instead

| you want | write |
|---|---|
| `if a > b` in the middle of a view | `when a > b { … }` as a guard |
| a computed string, `"" + x + y` | one `copy` and a `suffix:`, or ask the host for the formatted value |
| a total, an average, a count | a `source` field — the host computes it |
| a loop with an index you control | `for x, i in <collection> key x.id` |
| a function | a `component` |
| a variable | `state`, or a `source` |
| a per-frame update | nothing — declare the dependency and the runtime re-renders |
| a colour, a font size, a corner radius | nothing — the kit decides. If the REQUEST asked for a look, `theme <mood>` |

If none of those fit, the card you are trying to write is not an L0 card, and
forcing it produces a rejected one. Say what you can and leave the rest out.
