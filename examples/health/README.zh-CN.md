# 体检预约流程

[English](README.md) | 简体中文

一张生成的总图提供了十二个经过测量的原生场景，以及十二个可独立挂载的体检 / 日历服务卡片。应用内的邀请引出桌面上的预约卡片、可选项目、结合日历的时段选择、预约、日历确认 / 撤销 / 恢复、草稿修改、显式取消，以及最终摘要。

服务机构、预约以及已有的日历冲突都是虚构的本地 fixture。牙科和视力检查是机构提供、由用户自选的项目；本流程不给出任何医疗建议，不提供临床指导，不报告任何检查结果，也不会创建真实预约。

## 来源与分辨率

- `source/atlas.png` 是一次内置图像生成调用的原始输出，未经改动
- `source/prompt.txt` 是覆盖全部十二个画面的完整原始提示词
- 请求分辨率：**2400 × 3456**，最高支持细节
- 实际原始 PNG：**962 × 1635**；这仍是一张**草稿分辨率的源图**
- 工具没有暴露模型身份；不宣称使用了任何特定图像模型
- `source/generation-receipt.json` 记录了这些限制以及原始生成文件的位置
- `pipeline-output/intake-v2` 记录了不可变的原始字节、无损裁切，以及到 406 × 776 画板的等比变换

812 × 1552 的参考图是派生的布局参考，而不是新生成的细节。原生场景使用真实的标签和按钮。场景素材中唯一附带的位图是第一个画面里经过核查、不含文字的候诊室照片。图标是描摹出的矢量图；源图中的风景壁纸用原生纯色表面近似。截图和完整参考图都不会作为 UI 发布。

## 文件

- `image-to-appcard-flow.json`：可复用的流水线 manifest
- `cards/health-01` 到 `cards/health-12`：经过测量的原生 contract、语义映射、源图测量、编译出的 L0/kit/data/mapping，以及控件绑定
- `pipeline-output/service-cards`：十二个提取出来、归属于各服务的原生卡片子树
- `wizard/card-bundle`：可移植的编译场景 bundle 及素材来源记录
- `wizard/service.mjs`：自包含、不可变的双语浏览器服务模型
- `wizard/service.test.mjs`：行为、范围、幂等、本地化和绑定测试
- `route_test.json`：四条完整的原生点击路线，覆盖禁用控件、修改、取消、Back 和 Restart
- `evidence/contract-validation.json`：覆盖全部十二个场景的 126 项双语路线 / contract 绑定检查

## 行为

周六 09:00–10:00 与已有的个人日程冲突，因此被禁用。周日的同一时段可选。切换日期会清空已选时段。确认后会创建一个稳定的预约和一个关联的日历事件。可选的牙科 / 视力项目始终是用户的明确选择。

日历确认只改变“已阅”状态。日历撤销只移除关联事件，体检预约仍然有效。恢复时复用同一个事件 ID。草稿修改在确认前保留原已预约的时段。确认修改会更新同一个预约和已有的关联事件；之前被移除的日历事件在用户恢复之前保持移除状态。

打开取消卡片不会产生副作用。确认取消会取消预约并移除其关联事件，同时保留无关的个人日程。重放的事件 ID 不会重复生效；把一个 ID 用于不同操作，或提交过期 / 已禁用的控件，都会被拒绝。Back 恢复本地模拟快照，Restart 创建全新的本地场景。没有任何定时器会自动推进流程。

原生 Studio 和浏览器的视觉验收由上层集成工作流单独执行。编译产物和模型测试并不代表视觉验收已通过。
