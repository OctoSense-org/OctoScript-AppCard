# 老同学，慢慢聚 / 一场安排妥当的聚会

[English](README.md) | 简体中文

这是一个确定性的、双语的服务 AppCard 演示。熟悉的“信息”画面承载原始邀请和活动详情；桌面上则是分属不同服务的聚会、日历和费用分摊卡片。每个文字标签和控件都是原生 Makepad 控件。任何邮件、日历或支付操作都不会触达真实服务。

| 场景 | 界面 | 交互 |
| --- | --- | --- |
| 01 | 信息应用 | 打开王宁发来的聚会邀请 |
| 02 | 信息应用 | 阅读邀请和场地照片；打开时间投票或活动详情 |
| 03 | 桌面聚会卡片 | 开始选择时间 |
| 04 | 展开的投票卡片 | 周五与工作会议冲突，已禁用；选择周六或周日 |
| 05 | 展开的投票卡片 | 确认所选偏好，或重新选择 |
| 06 | 桌面 RSVP 卡片 | 已记录 RSVP；在添加日历事件前等待组织者明确更新 |
| 07 | 分开的聚会卡片和日历卡片 | 组织者确认场地和时间；确认或撤销日历条目 |
| 08 | 分开的聚会卡片和日历卡片 | 恢复同一个日历事件；RSVP 保持已确认 |
| 09 | 分开的付款卡片和 RSVP 卡片 | 核对 ¥180、收款人王宁和聚会用途；明确付款或取消 |
| 10 | 付款取消卡片 | 重新打开付款请求；RSVP 保持已确认 |
| 11 | 不可变的付款凭证 | 查看固定凭证，并打开活动详情 |
| 12 | 聚会应用详情 | 一起查看邀请、RSVP 和付款记录；返回桌面 |

组织者 fixture 确认的时间是 2026 年 10 月 24 日（周六）18:30，地点为桂花路8号的木光餐厅。周日的偏好仍被记录，组织者随后选定周六这一决定会被明确指出。日历的撤销和恢复保留事件 ID `calendar-reunion-2016`。费用分摊是组织者的第二次明确更新。付款凭证只由 `pay_contribution` 创建，ID 为 `REU-20261024-001`；取消付款永远不会改变 RSVP 或日历事实。Back 改变可见界面，但保留服务事实。Restart 开始一个全新的演示会话。

## 来源与重建

`source/atlas.png` 是**一次**内置图像生成调用的原始结果，覆盖全部 12 个画面。提示词要求最高质量和 2400×3456。工具返回的是 **1045×1505**，且没有暴露模型标识，也没有尺寸 / 质量参数。`source/generation.json` 记录了这一限制和原始哈希。归一化后的 812×1552 帧参考是放大后的评审输入，而不是新生成的高分辨率图像。

`source/crops.json` 记录测量得到的裁切矩形。`source/atlas.ocr.json` 保留源图 OCR。`scripts/author.py` 以原始面板像素记录了卡片、按钮、图标和照片的测量矩形。它声明了 OCR 修正和有意的 UX 改进，包括场景 07 中两个分开的日历操作。每个场景都保留其源图测量、参考哈希、语义映射和编译出的 L0/kit/data/mapping。

原生重建使用 410 个节点，其中 178 个是 Label。Noto Sans SC 字形度量使源文字在宽度和高度上都能放下。浏览器文案以中英文覆盖当前场景的每个标签，并带有动态原生文字、启用状态和选中样式。原生 View 用淡鼠尾草色表面近似装饰性的植物桌面背景。SVG 线条图标是重建的矢量图。位图裁切只包含联系人头像和场地照片；浏览器 bundle 中没有整屏位图、栅格化的 UI 标签或截图热点。

## 产出

- `cards/reunion-01` 到 `cards/reunion-12`：经过测量的原生场景源文件和编译产物
- `service-cards/catalogue.json`：14 个按各自尺寸独立的原生子树，明确归属于 reunion、calendar 或 payment
- `wizard/service.mjs`：自包含、不可变的服务 reducer 和双语视图模型
- `wizard/card-bundle/`：12 个编译后的场景载荷、引用的素材和源文件哈希来源记录
- `route_test.json`：采用共享运行器 schema 的两条点击路线，覆盖禁用控件和全部 12 个场景
- `pipeline-output/intake/`：不可变的源图 intake 回执，以及未改动的 atlas / 提示词副本

bundle 包含 83 个已声明的素材文件，主要是 SVG 图标。其导出器会检查素材声明，并排除已知的参考图和 atlas 哈希。intake 中的“native mapping not started”状态描述的是 intake 操作本身；原生重建由 `author.py` 另外完成。

## 在服务项目中复现

在本目录下运行，前提是上两级目录已安装现有的固定版本流水线及其 Python 虚拟环境：

```sh
../../flows/image-lib/.venv/bin/python scripts/author.py
python3 scripts/build_service.py
node --test wizard/service.test.mjs
../../flows/image-lib/.venv/bin/python scripts/export.py
```

author 和导出器会把编译器的素材发布重定向到本项目的 `artwork/` 目录。它们从不写入共享的 Studio 请求。已有的独立提取结果只在其源场景哈希仍然匹配时保留；修改原生源文件后，请保留先前的提取结果，并用可复用的 `extract.py` 工具选择新的输出目录。浏览器集成请使用上层项目共享的渲染器和宿主；本目录不构建也不修改共享的 WASM 运行时。
